# CAL-07 별도 후속 수정

## 확정 기준
- 시간 일정: 시작 24시간 전에 사이트 알림. 예: `내일 19:00 ‘정기 회의’ 일정이 있어요`.
- 종일 일정: 전날 오전 9시에 사이트 알림. 예: `내일 ‘정기 회의’ 일정이 있어요`.
- 알림 시각이 이미 지난 일정은 예약하지 않으며 즉시 발송하지 않는다. 수정 전 대기 예약은 취소한다.
- 자동 일정은 일반 일정 알림에서 제외한다. 공모전 D-7·D-1은 별도 TEAM_DEADLINE 경로에서만 발송한다.
- 기존 잘못된 시작 시각 정책으로 저장된 EVENT/PENDING 예약은 1분 주기 보정에서 교체한다. 이미 SENT인 알림은 다시 보내지 않는다.
- 실제 발송은 기존 5분 주기 fireDue가 처리하므로 예약 시각과 최대 한 주기 정도 차이가 날 수 있다.

## 공모전 마감 변경
- 관리자 수정에서도 마감일이 실제 변경되면 ContestDeadlineChangedEvent를 발행한다. 제목·카테고리만 변경하면 발행하지 않는다. 기존 저장 트랜잭션의 자동 일정 갱신은 유지한다.
- ContestDeadlineChangedEvent AFTER_COMMIT에서 CAL-06 자동 일정 갱신(Order 0)을 먼저 실행한다.
- 알림 리스너(Order 1)는 별도 새 트랜잭션에서 최종 DB의 D-7·D-1 시각으로 예약을 보정한다. 이벤트 날짜 자체를 신뢰하지 않는다.
- 기존 1분 주기 보정도 유지한다. 자동 일정 갱신 실패는 기존 캘린더 리스너 로그에서 확인해야 한다.
- 수신 시점에 현재 DB 일정과 fireAt을 다시 비교하여 변경·삭제된 옛 예약을 보내지 않는다.

## #158 이후 남은 운영 확인
- 공식 기능정의서 BRD-002/NOTI: 커뮤니티 새 글 문구 `커뮤니티에 새 글이 올라왔어요: 제목`, 신청 회원 사이트만·기본 꺼짐·작성자 제외·수정 제외를 반영.
- 관리자 숨김: closePendingApplications가 반환하는 대기 지원자만 알림. 문구 `지원한 모집글 '제목'이 관리자에 의해 삭제되어 모집이 마감됐어요.` 수락·거절 지원자 제외, 팀·워크스페이스 유지.
- 공식 DB 명세서: crawler_job은 사용자 후속 요청에 따라 V31에서 삭제한다(서버 적용 전). V28·V29는 되돌리거나 수정하지 않는다.
- 외부 공식 시트는 아직 편집하지 않았다. 위 문구는 반영용 기준이다.
- 수형님/배포 담당자: admin_worker 서비스·cron 등록 여부 확인, 있으면 중지. 테스트 서버 V29 적용 상태와 정상 기동 확인. 팀원이 V29 적용을 전달했으나 이 작업에서 직접 DB를 조회하지 않았다.
