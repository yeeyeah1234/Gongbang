# 공방 관리자 기능명세

사용자가 제공한 관리자 화면 6장과 후속 요구사항을 기준으로 구현한다. 서버 배포 및 실제 DB·메일·Garage 통합 검증은 아직 수행하지 않았다.

## 화면과 기능

| 경로 | 구현 내용 |
|---|---|
| /admin/verifications | 인증 요청 목록·최근 처리 이력, 비공개 증빙 확인, 승인·200자 이내 사유 반려, 심사자·시각 기록, 실명 파기, 결과 알림·메일 outbox |
| /admin/notices | 운영 공지 작성·수정·소프트 삭제, 등록 시 전체 회원 사이트 알림. 이메일 발송은 협의 전까지 제외 |
| /admin/reports | 최신 접수순 신고 목록·필터·상세, 댓글/모집글 숨김, 닉네임 변경 요구, 경고·정지, 기각, 처리 이력 |
| /admin/members | 실제 회원 검색·상태 조회, 로그인 잠금 해제·실패 횟수 초기화, 경고·정지·해제·닉네임 변경 요구 |
| /admin/posts | 신고된 모집글 우선 조회, 강제 숨김과 CLOSED 전환, 지원자 전체 알림, 댓글 조회·숨김 |
| /admin/contests | 공모전 제목·마감일·카테고리 수정, 영향 팀 확인, D-7·D-1·마감 일정 재계산, 카테고리 이름·순서 수정, 수동 재수집 요청 |

실제 /admin 화면은 API 데이터를 사용한다. /dev/admin-preview/{메뉴}는 개발 모드에서만 열리는 샘플 미리보기이며 변경 사항은 메모리에서만 처리한다.

2026-11-24 화면 수정: 좁은 왼쪽 메뉴, 회색 프로필 카드, 상단 요약 띠, 목록·상세 2열, 회색 상세 필드, 신고 조치 선택 버튼, 목록 아래 최근 심사/크롤링 패널로 배치했다. 공통 서비스 색상 토큰을 사용하므로 흑백 와이어프레임과 색상이 완전히 같지는 않다. 왼쪽 프로필은 로그인한 관리자 닉네임을 표시하고, 비로그인 미리보기는 '관리자'로 표시한다.

## 관리자 권한

- 초기 관리자: 1007jjw@naver.com. V24 적용 당시 해당 이메일의 활성 기존 계정만 ADMIN으로 지정한다.
- 계정·비밀번호를 생성하지 않으며, 이후 가입한 계정을 자동 승격하지 않는다.
- 사용자의 최종 요청에 따라 다른 회원에게 ADMIN을 부여하는 UI는 없고 기존 권한 부여 API도 거부한다.
- 서버에서 현재 DB의 관리자 권한과 회원 상태를 검사한다. 서버 DB에 초기 관리자 지정이 적용됐다고 간주하면 안 된다.

## DB와 파일

기준 develop의 마지막 마이그레이션은 V23(uploaded_file, PR #119)이다. 공통 파일 테이블을 재사용하며 증빙은 비공개 저장소와 인증된 열람 경로를 사용한다.

- V24: 초기 관리자 지정.
- V25: 회원 제재 필드, report 심사 필드, comment 테이블.
- V26: crawler_job 및 실행 중 작업 중복 방지 키.

증빙은 본인과 관리자만 열람한다. 로컬 비공개 경로 또는 비공개 S3 저장소를 사용하며 JPG·PNG·PDF 형식과 5MB 제한을 검사한다. 실명 암호화 키는 고정 REAL_NAME_KEY가 필요하다. 기존 로컬 사진을 S3로 옮기는 작업은 자동 수행하지 않는다.

ERD 링크의 실제 스키마와 최종 대조 및 운영 DB Flyway 이력 확인은 별도 필요하다. 기존 적용된 마이그레이션은 변경하지 않는다.

## 운영 연동과 확인할 사항

- 수동 재수집은 crawler 디렉터리에서 python src/admin_worker.py를 별도 실행해야 한다. 기존 backend 출력 모드와 내부 키 설정을 사용한다. 실행 도중 worker가 종료된 RUNNING 작업의 자동 복구는 구현하지 않았다.
- D-7·D-1 알림은 한국 시간 오전 9시 기준으로 예약한다. 이 시각은 운영 정책 확인이 필요하다.
- 모집글 숨김은 팀·워크스페이스를 삭제하지 않는다. 종료 기준은 공모전 마감일에서 계산한다.
- 댓글은 조회·신고·숨김 연동 범위이며 신규 댓글 작성·답글 화면은 포함하지 않는다.
- 정지 계정의 로그인·토큰 발급 및 채팅 SEND/SUBSCRIBE를 제한한다. 기존 구독을 강제로 끊는 기능은 별도다.
- Google 로그인과 회원가입은 동일 SocialLoginButtons를 사용한다. 이메일이 같다는 이유만으로 계정을 자동 병합하지 않는다.

## 검증

프런트 TypeScript 빌드와 ESLint, 백엔드 Spotless와 단위 테스트를 실행했다. MySQL 환경 의존 테스트는 해당 DB가 없어 건너뛰며, 실제 SMTP·Garage·배포 서버 검증은 미수행이다. 관리자 신고·회원 화면은 로컬 브라우저 캡처로 배치를 확인했다. 개발 미리보기의 샘플 회원을 실제 회원으로 간주하지 않는다.
