# 공방 관리자 기능명세

사용자가 제공한 관리자 화면 6장과 후속 요구사항을 기준으로 구현한다. 서버 배포 및 실제 DB·메일·Garage 통합 검증은 아직 수행하지 않았다.

## 화면과 기능

| 경로 | 구현 내용 |
|---|---|
| /admin/verifications | 인증 요청 목록·최근 처리 이력, 비공개 증빙 확인, 승인·200자 이내 사유 반려, 심사자·시각 기록, 실명 파기, 결과 알림·메일 outbox |
| /admin/notices | 운영 공지 작성·수정·소프트 삭제, 등록 시 전체 회원 사이트 알림. 이메일 발송은 협의 전까지 제외 |
| /admin/reports | 최신 접수순 신고 목록·필터·상세, 댓글/모집글 숨김, 닉네임 변경 요구, 경고·정지, 기각, 처리 이력 |
| /admin/members | 실제 회원 검색·상태 조회, 로그인 잠금 해제·실패 횟수 초기화, 경고·정지·해제·닉네임 변경 요구 |
| /admin/posts | 신고된 모집글 우선 조회, 강제 숨김과 CLOSED 전환, 지원자 전체 알림, 댓글 조회·숨김 |
| /admin/contests | 공모전 제목·마감일·카테고리 수정, 영향 팀 확인, D-7·D-1·마감 일정 재계산, 카테고리 이름·순서 수정 |

실제 /admin 화면은 API 데이터를 사용한다. /dev/admin-preview/{메뉴}는 개발 모드에서만 열리는 샘플 미리보기이며 변경 사항은 메모리에서만 처리한다.

2026-11-24 화면 수정: 좁은 왼쪽 메뉴, 회색 프로필 카드, 상단 요약 띠, 목록·상세 2열, 회색 상세 필드, 신고 조치 선택 버튼, 목록 아래 최근 심사/크롤링 패널로 배치했다. 공통 서비스 색상 토큰을 사용하므로 흑백 와이어프레임과 색상이 완전히 같지는 않다. 왼쪽 프로필은 로그인한 관리자 닉네임을 표시하고, 비로그인 미리보기는 '관리자'로 표시한다.

## 관리자 권한

- 초기 관리자: 1007jjw@naver.com. V26 적용 당시 해당 이메일의 활성 기존 계정만 ADMIN으로 지정한다.
- 계정·비밀번호를 생성하지 않으며, 이후 가입한 계정을 자동 승격하지 않는다.
- 모든 활성·비정지 관리자는 회원 관리 화면에서 다른 활성·비정지 회원에게 ADMIN을 부여할 수 있다. 부여받은 관리자도 동일한 권한을 갖는다. 대상 확인 후 적용하며 서버에서 권한을 재검사하고 대상 행을 잠근다. 이미 ADMIN인 회원에게는 중복 적용하지 않는다.
- 서버에서 현재 DB의 관리자 권한과 회원 상태를 검사한다. 서버 DB에 초기 관리자 지정이 적용됐다고 간주하면 안 된다.

## DB와 파일

기준 develop의 마지막 마이그레이션은 V25(comment, PR #129)이다. 공통 파일 테이블 V23을 재사용하며 증빙은 비공개 저장소와 인증된 열람 경로를 사용한다.

- V26: 초기 관리자 지정.
- V27: 회원 제재 필드, report 심사 필드. 댓글은 develop의 V25를 재사용한다.
- V28: 기존 생성 마이그레이션은 체크섬 보존을 위해 수정하지 않는다.
- V31: 2026-11-26 사용자 요청으로 `crawler_job` 테이블을 삭제한다. 적용 시 기존 수동 재수집 작업 이력도 삭제된다. 팀 초대 PR #174(V30)는 2026-11-26 20:20 KST에 develop으로 병합되었다(04f7429). V30의 ID·FK 네 컬럼은 BIGINT UNSIGNED로 수정되어 있다. #173의 V31은 V30 서버 적용 성공을 확인한 뒤 적용한다. GitHub 배포 기록이 없어 V30 서버 적용 여부는 아직 확인하지 못했다. develop 병합 시 테스트 서버 자동 배포로 DROP이 실행될 수 있으므로 병합 전 배포 담당자가 기존 admin_worker 중지 여부를 확인한다. 작성 시점에는 서버 적용을 직접 확인하지 않았으며, 병합 후 실제 적용 상태는 Flyway 이력으로 확인한다.

공식 시트 정리 대상(아직 미반영): 기존 DB 명세서에 `crawler_job` 행이 있으면 운영 테이블에서 제외하고 삭제 이력에 관리자 수동 재수집 철회·V31 적용 시 삭제를 기록한다. 첨부받은 엑셀에는 해당 행이 없어 엑셀 DB 시트를 변경하지 않았다. 기존 ADM-06 행에서 수동 재수집만 제외하고 공모전 수정·영향 팀 확인·카테고리 관리는 유지한다. API 명세서에 관리자 재수집 요청 및 `POST /internal/contests/jobs/claim`, `POST /internal/contests/jobs/{id}/finish` 행이 있으면 운영 API 목록에서 제외하고 변경 이력에 철회 사유를 남긴다. 정기 수집용 `POST /internal/contests/batch`는 유지한다.

수동 재수집 제거는 이미 병합된 #158에 포함되어 있으므로 중복 제거 PR을 만들지 않는다. 이후 contest·crawler 관련 변경이 포함되는 PR에는 최규선 님께 리뷰를 요청한다. 공식 시트는 기존 행을 수정하며 별도 대체 명세를 만들지 않는다.

### 관리자 권한 부여 결과 알림 (2026-11-25 사용자 요청)

- 기존 권한 부여 확인창에서 확인하여 USER → ADMIN 변경이 성공하면 신규 관리자 본인을 제외한 활성·비정지 관리자 전원에게 사이트 알림을 저장한다. 권한을 부여한 관리자도 포함한다.
- 문구: `@닉네임 님이 관리자가 되었습니다!`, 이동: `/admin/members`. 이메일은 보내지 않는다.
- `ADMIN_GRANTED` 알림 종류(NOTICE 분류)를 추가한다. 시스템 알림(actor_id=NULL), 대상 MEMBER/신규 관리자 ID. 기존 varchar 컬럼을 사용하여 DB 마이그레이션은 없다. 공식 DB 명세서의 notification.type 허용값 반영은 담당자 확인이 필요하다.
- 권한 변경과 알림 저장은 같은 트랜잭션이다. 실패 시 함께 롤백한다. 기존 대상 행 잠금과 이미 ADMIN인지 검사를 유지하여 재요청은 중복 발송하지 않는다. 별도의 초대 수락 절차는 추가하지 않는다.

증빙은 본인과 관리자만 열람한다. 로컬 비공개 경로 또는 비공개 S3 저장소를 사용하며 JPG·PNG·PDF 형식과 5MB 제한을 검사한다. 실명 암호화 키는 고정 REAL_NAME_KEY가 필요하다. 기존 로컬 사진을 S3로 옮기는 작업은 자동 수행하지 않는다.

ERD 링크의 실제 스키마와 최종 대조 및 운영 DB Flyway 이력 확인은 별도 필요하다. 기존 적용된 마이그레이션은 변경하지 않는다.

## 운영 연동과 확인할 사항

- 2026-11-24 사용자 결정으로 관리자 수동 재수집 버튼·요청/claim/finish API·worker를 제거했다. 기존 정기 공모전 크롤러는 유지한다. 이전 admin_worker를 서버에 따로 등록했다면 배포 담당자가 해당 프로세스/스케줄을 중지해야 한다. 이 작업에서 서버 설정을 변경하지는 않았다.
- D-7·D-1 알림은 한국 시간 오전 9시 기준으로 예약한다. 이 시각은 운영 정책 확인이 필요하다.
- 모집글 숨김은 팀·워크스페이스를 삭제하지 않는다. 종료 기준은 공모전 마감일에서 계산한다.
- 댓글 작성·답글·조회는 develop의 공통 댓글 모듈을 사용하고 관리자 숨김 및 모집글 신고 기능을 연결한다.
- 정지 계정의 로그인·토큰 발급 및 채팅 SEND/SUBSCRIBE를 제한한다. 기존 구독을 강제로 끊는 기능은 별도다.
- Google 로그인과 회원가입은 동일 SocialLoginButtons를 사용한다. 이메일이 같다는 이유만으로 계정을 자동 병합하지 않는다.

## 검증

프런트 TypeScript 빌드와 ESLint, 백엔드 Spotless와 단위 테스트를 실행했다. MySQL 환경 의존 테스트는 해당 DB가 없어 건너뛰며, 실제 SMTP·Garage·배포 서버 검증은 미수행이다. 관리자 신고·회원 화면은 로컬 브라우저 캡처로 배치를 확인했다. 개발 미리보기의 샘플 회원을 실제 회원으로 간주하지 않는다.

2026-11-24 후속 검증: 관리자 6개 화면의 1920px 전체 화면 캡처와 375px 가로 넘침 검사를 완료했다. 개발 미리보기에서 인증 승인, 공지 등록, 신고 기각, 회원 잠금 해제, 모집글 강제 숨김, 카테고리·재수집 확인창을 확인했다. 이 검증은 샘플 API 응답을 이용하므로 실제 서버 통합 검증을 대신하지 않는다. 새 공지·카테고리·재수집 확인창에 다른 선택 항목이 표시되던 문제를 수정했다.

2026-11-24 최신 develop 통합 검증: 백엔드 730개 중 670개 통과·60개 DB 환경 의존 제외, 프런트 build/lint 통과. 관리자 6개 화면 375/768/1024px 가로 넘침 없음 및 미리보기 관리자 권한 부여·승인·공지 등록·신고 기각·잠금 해제·강제 숨김을 확인했다. 테스트 서버는 자동 요청에 HTTP 403을 반환하여 실제 DB·로그인·배포 검증은 하지 못했다. #117의 NotificationBell 반응형 폭/높이와 UserMenu compact/GNB 연결은 반영했고, 나머지 담당 화면 및 목록→본문 전환은 후속 작업이다.

2026-11-24 모바일 후속 변경: 1024px 미만 관리자 목록→상세 전환, 미선택 상세 미렌더링, 목록 복귀 버튼 및 접히는 관리 메뉴. 이전 캡처는 수동 재수집 제거 전 화면이므로 현재 화면 근거로 사용하지 않는다.
