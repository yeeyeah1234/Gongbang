# MY-02 내 글 관리

2026-11-24 사용자 요청: 지원한 모집글과 작성한 게시판 글 탭 추가, 표시되지 않는 댓글 목록 연결.
기존 프런트는 `/api/members/me/comments`를 호출했으나 서버에 조회 API가 없었다.

## 탭
- 모집글: 기존 작성 모집글 조회·수정·선택 삭제 유지.
- 지원한 모집글: 현재 로그인 회원이 지원한 모집글과 지원일, 대기/수락/거절/종료 상태. 공모전 자체에 직접 지원한 기록을 뜻하지 않는다.
- 게시판: 본인이 작성한 활성 커뮤니티 게시글. 상세·수정 화면으로 이동.
- 댓글: 모집글·게시판에서 본인이 작성한 댓글과 답글. 본인 비공개 댓글 포함. 댓글/원문이 삭제·숨김된 경우 제외. 각각 올바른 원문으로 이동.

각 탭 최신 작성/지원 시각과 ID 내림차순, 기본 10개씩 페이지 조회. 삭제된 모집글의 지원 이력은 제목을 마스킹하고 링크를 제공하지 않는다. 취소된 지원은 기존 정책상 행이 삭제되므로 목록에서 제외된다.
1024px 미만에서는 표 대신 카드, 탭은 줄바꿈. 빈 목록·조회 실패·재시도 구분.

## 조회 API 추가 (공식 명세 반영 대상)
모두 로그인 필요, 요청 파라미터 `page=0`, `size=10` (page >= 0, size 1~100).
회원 ID는 요청값 대신 인증 사용자로 고정한다. 다른 도메인 repository를 직접 호출하지 않고 해당 도메인에 controller/service/query를 둔다.

| 경로 | 항목 필드 |
|---|---|
| GET /api/members/me/applications | applicationId, postId, title, status, deletedAt, createdAt |
| GET /api/members/me/board-posts | boardPostId, title, category, createdAt |
| GET /api/members/me/comments | commentId, postId, boardPostId, postTitle, content, createdAt |

댓글의 postId/boardPostId는 대상에 따라 한쪽만 값이 있다. 공통 ApiResponse/PageResponse(items, page, size, totalCount, hasNext)를 사용한다. 잘못된 페이지 범위는 INVALID_INPUT, 비로그인은 UNAUTHORIZED. 빈 목록은 items=[], totalCount=0, hasNext=false.
DB 테이블/컬럼/마이그레이션 추가 없음. 지원·게시판 탭과 API는 이번 사용자 요청으로 확장한 범위이며 팀 공식 API 명세에도 반영이 필요하다.

## 검증
- 서비스: 로그인 누락·잘못된 페이지 차단, 본인 ID와 페이지 전달, 전체 개수/다음 페이지 처리.
- 컨트롤러: 클라이언트가 memberId를 바꿔도 인증 회원 ID 사용.
- MyActivityMysqlTest: 타인/삭제 필터, 모집글·게시판 댓글, 비공개 댓글, 페이지 정렬, 삭제된 모집글 지원 이력 및 취소 처리. TEST_DATASOURCE_URL이 _test 스키마일 때만 실행하며 트랜잭션 롤백.
- 실제 테스트 DB와 브라우저 연결이 없어 MySQL 통합 및 실제 회원 화면 검증은 미수행.
