## 담당자에게 전달할 확인 사항

- 이상현님: CONTEST_D7/CONTEST_D1 자동 일정의 날짜를 기준으로 오전 9시에 TEAM_DEADLINE 알림·메일을 생성한다. 일정 변경 시 기존 예약 취소/재계산 연결은 유지한다. 일반 EVENT_REMIND는 이메일을 보내지 않는다.
- 김수형님 리뷰 반영: 작성자 삭제와 관리자 강제 숨김 모두 closePendingApplications가 반환하는 대기 지원자만 받는다. 수락·거절 지원자는 제외한다. 관리자 문구는 `지원한 모집글 '제목'이 관리자에 의해 삭제되어 모집이 마감됐어요.`이며 팀·워크스페이스는 삭제하지 않는다. POST_DELETED 사이트·이메일 설정을 각각 적용한다.
- 위 내용은 전달용 정리이며 팀원에게 실제 메시지를 발송한 것은 아니다.

- NOTI-05/06: 팀 공모전 D-7·D-1은 WORKSPACE 이메일 설정을 따르는 IMMEDIATE 메일이다.
- 모집글 삭제는 POST_DELETED 설정을 따르는 IMMEDIATE 메일이다. 인증 결과는 수신 설정과 관계없이 IMMEDIATE 메일이다.
- 기존 야간(22~08시) 보류와 일반 메일 하루 10통 제한을 유지한다. IMMEDIATE는 즉시 SMTP 호출이 아니라 대기열 등록을 뜻한다.
- 운영 공지는 전체 회원 사이트 알림을 유지한다. 정책 변경 공지에 한해 관리자가 이메일 발송을 선택할 수 있다. 등록·수정 요청의 policyChange/sendEmail은 기본 false이며, 정책 변경이 아닌 이메일 요청은 거부한다. 이미 이메일을 요청한 공지에 대한 중복 요청은 재발송하지 않는다.
- service_notice에 policy_change(boolean, 기본 false), email_queued_at(datetime, nullable)을 V29로 추가한다. email_queued_at은 대기열 등록 시각이며 실제 발송 완료를 의미하지 않는다. 수정 시 행 잠금으로 중복 요청을 직렬화한다.
- 관리자 공지 목록 응답에 policyChange/emailQueuedAt을 추가한다. 기존 등록·수정 API 경로는 유지한다.
- 커뮤니티 새 글은 COMMUNITY_NEW 설정을 명시적으로 켠 회원에게 사이트 알림만 보낸다. 기본 꺼짐, 작성자 제외, 수정에는 발송하지 않는다. 글 생성 트랜잭션에서 이벤트를 발행하고 AFTER_COMMIT 리스너가 전용 작업 큐로 넘긴다. 롤백된 글은 알리지 않는다. 수신자별 별도 트랜잭션에서 저장하므로 알림 실패가 글 등록이나 다른 수신자 알림을 취소하지 않는다. BOARD_POST_NEW는 NOTICE 분류, BOARD_POST 대상, /board/{id}로 연결하며 문구는 `커뮤니티에 새 글이 올라왔어요: 제목`이다.
- 처리 방식: 전용 작업 스레드 1~2개, 대기 작업 최대 100개. 큐 초과·수신자 실패·대상 조회 실패는 글/회원 ID 및 오류 종류만 로그에 기록한다. 요청 스레드에서 알림 작업을 대신 실행하지 않는다. 정상 종료 시 20초까지 기다린다. 메모리 큐이므로 강제 종료·큐 거부 시 유실 가능성이 있고 자동 재시도/전달 보장은 없다. 내구성 있는 재처리가 필요하면 별도 DB outbox 정책·스키마를 합의해야 한다.
- 공식 기능·DB·API 명세서에도 위 정책과 새 알림 종류/설정값을 반영해야 한다. 현재 파일은 사용자 요청에 따른 구현 기준이며 외부 명세서 수정 완료를 뜻하지 않는다.
